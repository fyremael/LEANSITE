# Development guide

## Repository map

```text
LeanSite/Path.lean       private Route representation, smart constructors, and base-path operations
LeanSite/Html.lean       HTML algebra, escaping, and serialization
LeanSite/Markdown.lean   Markdown-lite parser and renderer
LeanSite/Site.lean       site model, graph validation, layout, and emission
LeanSite/Example.lean    executable example site
LeanSite.lean            public library imports
Main.lean                command-line interface
Tests.lean               executable regression tests
preview/                 checked-in example output for inspection
```

## Local checks

Run the same core checks used in continuous integration:

```sh
lake build
lake exe leansite_tests
lake exe leansite check
lake exe leansite build
```

A change to rendering should normally be accompanied by an exact-output regression test in `Tests.lean` and an updated checked-in preview when visible output changes.

For GitHub Pages behaviour, inspect the generated `_site/` tree and verify that links begin with `/LEANSITE/` while output directories remain unprefixed.

## Route invariant discipline

`Route.mk` must remain private. Public functions that return `Route` must establish the complete segment policy before invoking the private constructor.

Changes to the route policy require all of the following:

1. update `Route.isSafeSegment`;
2. keep the proof-based `Route.ofSegments` and dynamic `Route.fromSegments`/`Route.parse` paths equivalent;
3. add acceptance and rejection tests for every new rule;
4. update route semantics in `README.md`, `docs/USAGE.md`, and `docs/DESIGN.md`;
5. verify URL rendering and filesystem directory construction still consume the same segment representation.

Do not add a public string-to-route coercion, unsafe constructor, default fallback, or parser that silently substitutes `Route.root` after failure. Dynamic callers must receive `Except Route.Error Route`.

Graph-level validation remains separate. Duplicate routes and missing navigation targets depend on relationships among valid values and therefore still belong in `Site.validate`.

## General change discipline

Parser changes should document the accepted syntax and at least one rejected or deliberately unsupported edge case. Base-path changes should preserve the separation among logical routes, deployment-prefix resolution, public URL generation, and output-path generation. Rendering changes should keep untrusted text in `Html.text` and avoid `Html.rawTrusted` unless the value was produced wholly inside the trusted generator.

The public Pages demo must be generated by `lake exe leansite build`; do not maintain a separate hand-authored deployment tree.

## Continuous integration

`.github/workflows/ci.yml` compiles every target, validates the example site, and runs the regression executable on pushes and pull requests.

`.github/workflows/pages.yml` repeats the build contract on `main`, generates `_site/`, and deploys that artifact through GitHub Pages.

## Versioning

The package version lives in `lakefile.lean`. Until the feature contract stabilizes, minor releases may add syntax and fields while patch releases should be restricted to compatible fixes and documentation.
